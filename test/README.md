# 雷伊对盖亚：命令行战斗

在项目根目录用 PowerShell 启动：

```powershell
.\test\run-seer.ps1
```

默认控制雷伊，盖亚由电脑选招。输入技能序号；回车选择第一项，`0` 跳过，`q` 退出。双方选完行动后，才按先制和速度执行技能。

启动脚本兼容 Windows PowerShell 5.1 和 PowerShell 7。`run-seer.ps1` 含中文，必须保存为 **UTF-8 with BOM**；5.1 读取不带 BOM 的 UTF-8 时可能报“字符串缺少终止符”，即使报错指向 `--pvp` 等英文行。脚本内设置终端 UTF-8 只能在解析成功后生效，不能代替文件的编码标记。

```powershell
# 双方自动，适合复跑验证
.\test\run-seer.ps1 -Auto

# 双方都由键盘输入
.\test\run-seer.ps1 -Pvp

# 手动指定 Lua 5.5
.\test\run-seer.ps1 -Lua 'F:\lua\lua55.exe'
```

也可以直接运行 `lua55 test/seer_battle.lua --auto`。需要 Lua 5.5，现有异步库使用了它的语法；本机默认 `lua` 是 5.3，不能直接运行。启动脚本使用 PATH 中的 lua55，或者显式传入 -Lua 路径；运行时由使用者自行安装，不依赖开发者本机临时目录。

## 文件与职责

- `seer_data.lua`：雷伊、盖亚的完整测试面板、性格、个体、技能定义。数据可直接修改，均为示例配置，不是正式图鉴数值。角色数据为 `{ pets = {...}, items = {...}, activePetId = ... }`，当前仍各带一只精灵，便于单精灵战斗验收。
- `../packages/standard/effects/stage_change.lua`、`fixed_damage.lua`：标包通用能力变化与追加固定伤害骨架；测试不再单独注册技能效果。
- `seer_battle.lua`：初始化真实 sr 引擎、游戏模式和上下文，将宿主输入输出接到终端；展示技能说明、能力等级变化、未命中和实际回复/伤害类别。
- `run-seer.ps1`：启动入口和终端 UTF-8 设置。
- `../tests/battle_flow.lua`：覆盖既有战斗流程、四招效果，以及标包参数复用、校验与实例隔离。

## 测试数据与执行流程

雷伊为 100 级、开朗、个体 31；盖亚为 100 级、固执、个体 29。性格编号为本测试自定，面板已直接填写；当前未根据性格和个体重新计算面板。

雷伊固定按以下顺序携带四个技能：

| 序号 | 效果 | 实现入口 |
| --- | --- | --- |
| 1 | 自身除特攻外各项能力提升 3 级 | 标包 10016，`{target="self", exclude={"spatk"}, stages=3}` |
| 2 | 目标随机能力总计降低 3 级 | 标包 10016，`{target="target", mode="random_total", stages=-3}` |
| 3 | 自身回复 100 点体力，3 PP | 复用标包 10013 回复骨架 → `ctx:recover` |
| 4 | 威力 100 物理攻击，随后额外 50 点固定伤害 | 标包 10017，`{amount=50}`，类别 `sr.FixedDamage` |

能力集合是攻击、防御、特攻、特防、速度、命中，不包含体力；因此技能 1 同时强化其余五项。能力等级受 -6～+6 限制。技能 2 每次随机选择一项降低 1 级，可重复抽中同一项；排除已到 -6 的项，全体到下限时不再变化，剩余可降等级不足 3 时只降低剩余等级。先汇总变化量，再交给统一能力事件，仍可被前置效果阻止或修改。

技能 3 不超过体力上限。技能 4 两段使用独立伤害事件，不将 50 加进基础伤害；未命中时不追加，基础伤害已使目标倒下时不继续追加，剩余体力不足 50 时日志显示实际扣除量。首版没有给该技能额外定义“无视免疫”规则，伤害仍经过现有伤害时机。

盖亚保留两个攻击技能与回复技能。电脑选择当前威力最高且 PP 可用的技能，暂不考虑回复策略；`-Auto` 也使用该策略控制雷伊，因此自动模式不会依次演示四招。手动建议先输入 `1`、`2`、`3`、`4`，观察强化、弱化、回复和两段伤害。

测试使用项目实际的 GameThread、Context、Logic、GameEvent、技能和 HP 结算：

```text
seer.init 自动安装标包骨架 → 注册测试技能配置与游戏模式 → 创建上下文 → run
  → createSkill 按技能 effects 配置创建独立效果实例
  → 导入雷伊和盖亚 → 双方选择 action → 排序 → 使用技能
  → 伤害/回复与 HP 同步 → 下一轮或战斗结束
```

只用命令行替代 C++ 宿主的网络输入输出，不建立真实网络连接，也不读取数据库。元素属性随精灵数据导入，但当前通用伤害公式尚未接入属性克制；本次没有改动业务结算规则。

## 实际验收

- 自动对战：雷伊第 3 轮获胜；普通攻击先扣 102，再扣固定伤害 50，最后一击倒下后不追加。
- 脚本输入手动对战：依次选择 `1`、`2`、`3`、`4`，验证五项各 +3、目标随机合计 -3、回复封顶、两段伤害和胜负结束。弱化结果随房间随机源变化。
- 自动回归验证回复整整 100 及封顶、强化封顶与保留特攻、随机弱化下限/全体到底、普通伤害之后独立固定 50、未命中不追加和倒下不追加。
- 每局确认双方先提交行动再攻击，并检查战斗事件栈、技能效果范围和触发栈均清理完毕。
- 当前 64 组流程测试、6 组 Pattern 测试通过，包含既有异常流程。可运行 `lua55 tests/battle_flow.lua` 与 `lua tests/pattern.lua`。

本次四招不附带异常效果；既有异常流程仍由回归测试覆盖，没有额外增加异常招式。仍未实现：真实客户端通信、持久化、正式精灵/技能配置、面板计算、完整属性与暴击规则、换宠与道具。没有新增数据库表。`test` 是手动战斗入口，`tests` 是自动回归测试。

特殊行动出现时输入 `a1`、`a2` 等序号；选项由服务端提供。需要在可信队伍数据中配置后备精灵或 items 库存才会出现相应选项。协议见 [行动说明](../docs/action-protocol.md)。

# 效果脚本中的描述翻译与 I18nContext

## 当前项目实际用什么

当前可执行的翻译入口是 `sr:translate(key, language)`。名称与描述保留 key，显示时再查翻译表，不在加载效果脚本时把它们替换成某一种语言。

标准效果现在统一使用下面的结构，完整实例见 `packages/standard/effects/heal.lua`：

```lua
local effect = sr.createEffectSkeleton {
    id = 10013,
    name = "standard.effect.heal",
    event = sr.SkillHit,
    -- 简短的必要参数检查、触发与执行回调……
}

effect.description = effect.name .. ".description"
effect.translations = {
    zh_CN = {
        [effect.name] = "回复体力",
        [effect.description] = "自身血量低于设定比例时，回复指定数量的体力。",
    },
    en_US = {
        [effect.name] = "Recover HP",
        [effect.description] = "Recover the configured amount of HP when the owner is below the configured HP ratio.",
    },
}

return effect
```

这里 local effect 实际仍是静态骨架。安装包时，Package 加载各骨架的 translations，再加载包自己的 translations；同语言同 key 冲突时，包级文本后加载并覆盖。技能和 Buff 名称继续放在包的 i18n/zh_CN.lua、en_US.lua；效果名称和描述已移动到各自效果文件。

实际 Effect 从骨架继承 description key。可以这样显示：

```lua
local effect = sr:createEffect(10013, { hpBelow = 0.5 }, { amount = 50 })
local name = sr:translate(effect.name, "zh_CN")
local description = sr:translate(effect.description, "en_US")
```

缺少目标语言时回退中文，再回退 key。当前示例描述是静态规则说明，不自动把 hpBelow、amount 拼进文本。当前 translate 也没有实现下面宿主接口的 %1 占位替换、语境或复数规则。

## meta.lua 为什么写空函数

`basescripts/corelib/meta.lua` 第一段为：

```lua
-- Helpers for LSP
do return end
```

这意味着文件运行到这里就返回了。后面的 `---@class I18nContext` 和空函数只是给编辑器提供类型、补全提示，不会创建翻译器。不能 require 这个文件后调用里面的 local I18nContext，它也没有导出这个局部变量。

`basescripts/core/plugin.lua` 中的 i18nContext 同样只是字段注解，当前 Plugin.initialize 并没有为它赋值。

## 原参考项目里的真正实现

已核对本地 `seer-asio/reference/ktabletop` 源码：

- src/app/client-lua.cpp 的 injectI18nContext 为插件注入 plugin.i18nContext。
- 这是 C++ userdata，方法从第一个 Lua 参数读取自身，因此实际使用冒号调用。
- src/app/catalog.cpp 根据语言读取插件的 i18n/<语言>/ktabletop-plugin-<插件目录名>.po，通过翻译目录查找文本。
- 未找到翻译时回退源文本；这不是自动机器翻译。

以下示例仅适用于已由原宿主注入 i18nContext 的环境，不能直接粘贴到当前独立终端脚本里运行：

```lua
local tr = plugin.i18nContext
tr:i18n("Recover %1 HP", 50)
tr:i18nc("effect description", "Recover %1 HP", 50)
tr:i18np("Recover %1 point of HP", "Recover %1 points of HP", 50)
tr:i18ncp("effect description", "Recover %1 point of HP", "Recover %1 points of HP", 50)
```

| 方法 | 含义 |
| --- | --- |
| i18n(text, ...) | 普通文本翻译，并替换 %1、%2 等参数 |
| i18nc(context, text, ...) | 增加语境，区分相同源文本的不同含义；context 本身不显示 |
| i18np(singular, plural, count, ...) | 根据数量和目标语言规则选择单数/复数；数量也是第一个替换参数 |
| i18ncp(context, singular, plural, count, ...) | 同时使用语境和复数规则 |

c 可以理解为 context，p 可以理解为 plural。中文通常不区分单复数，英文等语言需要；语境则可区分“技能名称中的回复”和“描述里的回复”等含义。真正翻译仍需对应的翻译条目。

当前项目先继续使用已跑通的 Lua key 字典，不引入 Qt 客户端或 .po 加载器。将来接入真正客户端后，可以在显示层对接宿主翻译器，不影响两组效果参数或战斗逻辑。

## 校验为什么保留一点

标准效果仍保留短小的必要检查，例如回复量是非负整数、血量阈值在 (0, 1]、能力名称有效。已删除回复条件的重复类型检查、未知条件字段遍历，以及强化参数的重复表类型检查和未知字段遍历。

CSV 格式、编号、引用、两组参数是否为普通表和实例参数隔离仍由公共层处理。业务脚本主要展示触发条件和效果执行，不再为每个字段重复铺开防御逻辑。
